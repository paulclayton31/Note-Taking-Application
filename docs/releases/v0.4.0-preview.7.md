# v0.4.0-preview.7 — Gemini request compatibility and useful errors

- Use the documented REST responseFormat.text JSON Schema configuration, with a simpler schema and optional circuit graph instead of a required nullable object. Response size/step bounds remain enforced locally.
- Distinguish request format errors (400) from authentication (401), permissions (403), model availability (404) and quota (429). Invalid-key reasons reported as 400 are recognized separately.
- Display bounded Google error details with credential redaction instead of blaming all rejections on the API key. No request headers or notebook data are logged.
- Add the app version to the Calculate dialog title so the running executable can be identified.

Windows checks simulate schema rejections, invalid keys, permission errors, empty/malformed error bodies and redaction. Live API requests require the user's key and were not performed during development. The earlier generic message did not expose enough detail to establish the exact server-side cause.
