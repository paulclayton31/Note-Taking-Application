# Surface Notebook v0.3.3

PDF notebooks, PDF export, and improved vertical scribble erase.

## Download

- **Intel / AMD Surface:** [Windows x64 executable](https://github.com/paulclayton31/Note-Taking-Application/releases/download/v0.3.3/SurfaceNotebook-windows-x64.exe)
- **Snapdragon / ARM Surface:** [Windows ARM64 executable](https://github.com/paulclayton31/Note-Taking-Application/releases/download/v0.3.3/SurfaceNotebook-windows-arm64.exe)
- [SHA-256 checksums](https://github.com/paulclayton31/Note-Taking-Application/releases/download/v0.3.3/SHA256SUMS.txt)

Close the old app, download the matching executable, and open it. No ZIP extraction, separate .NET installation, Adobe Reader, or cloud service is required. Your library remains at **%LOCALAPPDATA%\SurfaceNotebook**.

## Try PDF import and export

1. Select **Import PDF** in the library header, or **Import PDF as notebook** in the workspace's library menu.
2. Choose a PDF. Its pages become a new notebook in the current folder, preserving order, physical sizes, and orientation.
3. Write, highlight, add typed notes, and use the lasso over the fixed PDF background. Your annotations remain editable and save locally. The original external file is unchanged and is no longer needed after import.
4. Open page actions for **Export page as PDF**, or choose **Export notebook as PDF** for every page in order.

Exports include paper backgrounds, pressure-sensitive handwriting, highlighter transparency, and typed notes. Ordinary source PDF pages retain vectors and selectable source text. Rotated/cropped pages and pages containing PDF annotations export their rendered background for consistent appearance. Newly typed notes export as glyph outlines.

PDF backgrounds survive restart, page/notebook duplication, and portable page round trips. Their paper size is fixed; paper customization remains available on ordinary pages. Progress and cancellation are available. Import saves the prepared notebook in one transaction; export verifies a temporary file before replacing the destination. Canceled or invalid imports do not leave partial notebooks, and canceled exports preserve existing files.

## Vertical scribble erase

Up-and-down scratch-outs now accept narrow overlap over connected handwriting. Horizontal and diagonal scratches remain supported, with safeguards for long diagram lines. One Undo restores the erased handwriting and scratch mark; a second Undo removes the scratch. Redo remains available, and scribble erase can be disabled in tool options.

Scribble erase affects handwriting and typed annotations; the printed PDF background stays fixed.

## Limits and library upgrade

- Import unlocked PDFs up to **100 MB and 200 pages**. Pages must be **3-36 inches** on each side; prepared notebook data is limited to **300 MB**. Split larger documents before importing.
- **PDFs with form or signature fields must be printed or flattened first.** Password-protected PDFs need an unlocked copy. Interactive forms, signature validation, attachments, and bookmarks are not notebook features.
- Page previews render at up to **192 DPI**, capped at 3072 pixels on the longer edge.
- This release upgrades the library to **schema 4**, creating **library-v032-backup.db** before migration. **Older app versions cannot open the upgraded library.** Portable pages now use version 3; versions 1 and 2 remain readable.

v0.3.2's library copy/delete actions, fully closable tabs, smoother navigation, saved pens, lasso actions, and writing toolbar remain available.

## Verification

Windows regression checks cover PDF sizes/orientation, cropped and rotated pages, visual export round trips, annotations and restart persistence, page/notebook duplication, portable pages, invalid/form input rejection, cancellation during preparation/export/database saving, migration backup, and vertical scratch-out Undo/Redo. The existing storage, recovery, input, and writing checks also run.

The pipeline builds standalone x64 and ARM64 executables, validates embedded versions, and runs a bundled PDF export/import round trip during x64 startup verification. Actual interface and export renders were inspected, including an independent PDF renderer. ARM64 is cross-built; native runtime checks run on x64. Physical Surface input still benefits from device feedback.
