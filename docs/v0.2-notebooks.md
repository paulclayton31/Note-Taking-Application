# v0.2 notebooks, autosave, and navigation

## Daily use

Choose a notebook in the sidebar, or select **New notebook**. Use **Add page** to extend the notebook. Both notebooks and pages can be renamed. **Notebooks** in the header hides or shows the sidebar.

Write with the pen. Fingers navigate; there is no option to turn touch drawing on. One finger moves the page, and two fingers zoom. Move the pen away from the screen before using touch gestures; pen proximity suppresses palm gestures. **Fit width** returns the page to a comfortable writing size. Mouse wheel moves vertically, Shift+wheel horizontally, and Ctrl+wheel zooms.

Saving is automatic and works offline. **Save now** or Ctrl+S flushes queued edits. The app waits for queued saves when closing. If saving fails, edits remain queued in memory, the status reports the error, and the worker retries. Closing remains canceled until saving succeeds; an individual page can be exported while investigating storage problems.

**Import page** or Ctrl+O opens a legacy `.stempage` file as a new page. **Export page** writes an editable page copy. Ctrl+N adds a page; Ctrl+Z and Ctrl+Y undo and redo.

## Recovery and local ownership

The app stores its library in `%LOCALAPPDATA%\SurfaceNotebook`. `library.db` contains notebook/page metadata and editable strokes, including stable identities, coordinates, pressure, and pen style. SQLite's WAL may contain committed changes while the application is open. Copy the folder as a backup after closing the app normally.

The library records whether the prior session shut down cleanly. After a crash or forced termination, SQLite recovers committed transactions and the app reopens the last selected page with a recovery notice. It never substitutes a new empty library if the existing library fails to open. A per-library lock prevents a second app instance from writing concurrently.

Recovery covers committed edits. An in-progress stroke or an edit still queued when the process or device stops may be lost. The visible **Saved locally** status is the commitment boundary.

## Implementation

- `NotebookDatabase` owns the SQLite connection, WAL/FULL durability settings, schema version, instance lock, library metadata, and transactional stroke changes.
- `AutosaveWriter` owns one ordered background queue. Database I/O and JSON serialization happen on that worker, not the UI thread. A failed write remains queued before later writes and is retried. Flush barriers and clean-shutdown markers follow all earlier edits.
- `MainWindow` coordinates notebook/page selection and captures only added/removed stroke data on normal edits. SQLite writes are incremental; undo/redo replaces the current page transactionally. Up to five recent page sessions remain cached, and all pages remain in the database.
- `InkHistory` stores up to 30 history states using shared private stroke copies. Undo/redo supplies editable clones. History is session-local and is reset when an evicted page reloads.
- `PageViewport` handles touch at the ancestor preview stage, applies pan/zoom to the page's visual transform, and persists settled view state. Ink remains in original page coordinates. Touch contacts, including their mouse promotions, never activate ink editing.
- `PenCanvas` accepts real stylus input only. Its real-time renderer delegates to WPF for registered pen devices and filters other device packets. Pen pressure and curve settings match v0.1.

## Build and verify

Use the .NET 10 SDK on Windows:

```powershell
dotnet build SurfaceNotebook.slnx -c Release
dotnet run --project tests/SurfaceNotebook.Checks -c Release --no-build
dotnet run --project src/SurfaceNotebook
```

Tests use isolated generated libraries, never the user's normal library. They test real process termination and SQLite recovery, simulated write failures and retry ordering, canceled close state, page isolation/cache eviction/reopening, pressure round-tripping, UI controls, synthetic touch routes, and viewport math. They cannot certify physical pen or touch performance.

The release pipeline builds standalone x64 and ARM64 applications, checks x64 bundle startup/rendering/database access against a temporary library, and publishes assets only after checks pass.

## Surface acceptance session

1. Compare small handwriting, fast loops, pressure transitions, and inverted-tip erasing against v0.1.
2. Rest your palm during writing. The page must stay still and acquire no finger ink. Move the pen away, drag with one finger, and pinch with two; neither gesture should add or erase strokes.
3. Write on several pages across two notebooks. Rename them, switch pages, close, and reopen. Check that notes, names, selection, and page positions survive.
4. After **Saved locally**, force-close the app and reopen. Check the recovery notice and the committed notes.
5. Import an existing v0.1 page; compare pressure-derived appearance and export/reimport the page.
6. Take notes for a full session and check responsiveness and memory. Record Surface/pen model, architecture, display scaling, and any accidental movement or input loss.
