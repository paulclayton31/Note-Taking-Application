# Workspace test and usability review

Reviewed on October 23, 2026 using the Windows WPF app, isolated test libraries, a real offscreen test window for input hit testing, routed interaction events, and rendered light/dark/portrait/compact layouts.

## Fixed in this update

| Finding | Result |
| --- | --- |
| The small toolbar grip's template contained only a non-interactive icon. | A visible hover/focus surface with a 44-DIP target now receives input. |
| Drag position reset on window/focus changes and was not saved. | Position is stored as fractions of the available travel and restored after resizing/reopening. |
| Every page visit created a tab. | Tabs identify notebooks. Pages stay in the current notebook tab. |
| Returning to a notebook relied on the five-page session cache to remember its recent page. | A separate persisted notebook-to-page map retains the last page after eviction, closing tabs, and restarting. |
| Page-name search carried across notebooks, sometimes making the next notebook look empty. | Search and favorite filters reset when the notebook changes. |

## Verification

- Converted preview.1 preferences with duplicate page tabs into distinct notebook tabs without losing the selected page.
- Switched pages through the actual page-list selection event, created pages, and switched notebook tabs; the tab count stayed constant within a notebook.
- Exceeded the page-session cache capacity, then checked each notebook's remembered page.
- Closed active and inactive notebook tabs, reopened them through the notebook selector, and verified persistence after reopening the library.
- Attached the app window offscreen to verify that the toolbar grip is actually hit-testable, rather than relying only on synthetic drag callbacks.
- Exercised mouse drag callbacks and routed finger drags, checking both palette movement and unchanged page/ink state.
- Dragged beyond every workspace boundary, docked top/bottom, resized to portrait/compact layouts, opened paper settings, and toggled focus.
- Checked that saved relative toolbar placement survives all those layout changes and a fresh app instance.
- Retained the existing checks for ink/pressure data, pen-only input, palm suppression, touch pan/zoom, ink/text history, highlighter attributes, precision eraser identities, text, paper geometry/migration, autosave ordering/retries, and killed-process recovery.
- Rendered the real UI in light/dark themes and at desktop, portrait, compact, and focus sizes.

These checks do not measure physical pen latency, palm recognition on a particular digitizer, or ARM64 execution. No live user notebook is opened by the test harness or screenshot capture path.

## Suggested next improvements

1. **Make zoom choices easier to reach with touch.** The whole-page view is useful for review, but the landscape screenshot shows relatively small writing content. Fit width and 100% currently live in a right-click menu. A small touch-friendly zoom menu could make switching between writing and reviewing more obvious.
2. **Remember writing presets.** Pen color, thickness, and pressure/monoline choice currently return to their defaults after restart. Saving favorite pens would reduce repeated setup for lecture notes.
3. **Add page duplication and reordering.** Page management currently covers creation, naming, and navigation. Duplicate and drag-to-reorder would make worksheet reuse and reorganizing lecture material much easier.
4. **Consider a vertical palette and handedness presets.** Free horizontal movement works in this update; a future vertical arrangement could suit left/right edges and different writing hands while freeing the top of the paper.

The next iteration should favor these everyday workflow improvements before adding more advanced STEM/AI controls.
